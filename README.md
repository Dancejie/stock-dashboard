# 交易看板：持仓、自选与组合回测

沪深股票研究工具。图表与技术指标、手动持仓、自选快速切换、同区间组合回测和条件单参考。

## 使用

1. 搜索股票，选择「＋ 当前股票」加入自选。点击自选股票名称可直接切换图表。
2. 按券商记录填写平均成本、持仓股数、当前可卖股数，点击「保存更改」。没有持仓的自选可留空。
3. 在「组合回测」中新建命名组合，加入股票、填写相同起止日期：
   - **资金比例**：总本金只投入一次；各股票按初始权重获得独立预算，可以采用不同技术策略。未分配部分保持现金，不自动再平衡。
   - **固定股数**：起点已有指定数量股票，期初市值由共同起始日收盘价计算；现金字段是额外现金，不重复算作股票本金。
4. 运行后核对实际共同日期、期初/期末资产、现金与各股票贡献。保存的是配置；每次运行重新获取行情。
5. 条件单参考读取**已保存的真实持仓**，再填写本次实际可用资金。均值回归已有仓位时，还需填写本轮原定预算、已买批数、止盈阶段。平均成本不能推断这些成交状态。

## 三种价格口径

- **手动平均成本**：当前账面盈亏、成本止盈止损、实盘网格基准。不会回填历史价格或改变历史区间收益。
- **前复权价格**：技术信号与策略研究，用整手、费用及现金账本模拟。复权价格对应的股数和现金不是历史真实券商流水；未建立公司行为账本。
- **不复权价格**：固定股数组合的价格收益。除权除息可能造成价格下降；本模式没有自动补入分红现金、送转股或拆合股，因此不能当成含公司行为的账户总收益。

## 回测约定

- 使用已完成日线；盘中报价单独显示，不拼入历史信号。
- 收盘确认信号，下一个有数据的交易日开盘尝试成交。开盘跳空后重新按预算、手续费与整手约束计算数量。
- 买入股份当日不可卖；成交考虑可编辑佣金、最低佣金、卖出印花税和滑点，现金不透支。
- 对停牌及一字涨跌停采用保守过滤。板块涨跌幅、申报数量、上市初期、ST、历史规则和成交量限制仍有简化。
- 分批退出统计完整交易周期盈亏；开放仓位计入期末净值，不计作已完成交易的胜率。
- 历史网格默认基准取评价首日开盘价；条件单使用人工成本/基准。都不读取未来收盘价。
- 组合取共同可用区间；中间缺失日线报错，不用未来价格补齐，也不把缺数据擅自当停牌。
- WFA 网格仅训练期寻优；其他策略使用界面参数。验证窗口独立从现金开始，不能相加为连续投资回报；展示候选数和未覆盖尾段，不宣布“策略有效”。
- Alpha 为同日期日超额收益 OLS 截距的年化点估计，未检验统计显著性；Beta 与实际年化波动分别报告。

## 条件单边界

回测与条件单参考共用 `quant-core.js` 的信号规则。输出仅针对最后一根已完成日线和用户提供的实际状态；无信号时显示等待。下一交易日开盘前应重新确认资金、可卖数量与行情。券商只支持盘中触价时，不能把这套收盘确认规则直接替换为触价单。

本项目不连接券商、不会自动下单或发送站外消息。原来未接入看板的本地 `monitor.js`/`proxy.js` 已由受限、鉴权的数据接口替代。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `index.html` | 原有图表、指标和股票搜索界面 |
| `quant-core.js` | 统一策略信号、成交、资金、持仓、统计和条件单参考 |
| `portfolio-engine.js` | 组合资金分配、共同区间、贡献拆解、滚动验证 |
| `workspace-ui.js/css` | 自选、持仓录入、命名组合、显式保存与冲突处理 |
| `dashboard-upgrade.js/css` | 数据适配、回测结果、相对基准分析与条件单界面 |
| `app.py` / `init_db.py` | FastAPI、SSO、按用户隔离的 PostgreSQL 工作区、行情代理 |
| `tests/` | 确定性账本、无未来数据、组合资金、工作区契约和后端测试 |

保存接口用版本号防止多页面覆盖；数据仅按 SSO 用户身份访问。运行时从平台注入的 `db.properties` 读取数据库配置，不提交凭据，不以浏览器 localStorage 保存业务数据。

## 验证

```sh
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

部署使用 Cowork 官方转换和校验工具，并对原作品执行 `redeploy`。离线测试通过不等于已经上线；在线数据源、保存/重载、桌面和移动端需在发布后再次验证。
